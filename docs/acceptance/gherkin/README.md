# Teamspace Gherkin 验收场景

这些 `.feature` 文件把项目的用户可见行为整理成可复核的 Gherkin 规格。前五份依据活动 bundle、当前 RPC/HTTP 契约、客户端交互和实现描述当前行为；第六份专门记录 Agent 协作的目标设计，不能视为已完成实现。它们尚未接入 Cucumber 自动执行。

## 范围

| 文件 | 覆盖能力 |
| --- | --- |
| `01-accounts-and-sessions.feature` | Team 账号、注册开关、会话、成员邀请与会话访问隔离 |
| `02-messaging-and-decisions.feature` | 时间线、提及、回复、附件、实时事件、决策和确定性服务流程 |
| `03-agents-and-workspaces.feature` | Agent 名册与模板、会话邀请、执行过程、个人/共享工作区、审批 |
| `04-knowledge-and-memory.feature` | 团队知识库、检索、会话记忆、待办与纪要 |
| `05-administration-and-runtime.feature` | 后台配置、模型供应商、诊断控制台、启动和持久化行为 |
| `06-agent-control-model.feature` | Agent 静默收件、缓存友好上下文、按需访问、工作区隔离和人类中继的目标设计 |

面向测试人员的详细测试范围、用例步骤、回归映射和记录模板见 [Agent 可控协作 QA 计划](../QA-AGENT-CONTROL.md)。

## 读法与边界

- 每个场景描述一个可观察结果；`假如/当/那么` 使用中文 Gherkin（`# language: zh-CN`）。
- 表格中的用户、会话、Agent 和文件均为隔离验收数据，不代表生产数据。
- 需要真实 LLM、Embedding、Docker、宿主机配额或浏览器实时推送的场景，应由具备相应依赖的运行环境执行；不能用 stub 结果冒充真实供应商验收。
- “系统事件”“Agent 阶段”等是用户可见的状态或活动摘要，不要求展示隐藏推理文本。
- 第六份中的场景是本轮明确提出的产品设计目标。与活动实现的差距见文件末尾的“实现差距”，后续应先按此目标调整，再把场景接入运行验收。
- 历史文档提到的 `/models`、旧管理桥接页、暂存工作流和旧的全局会话限制不作为当前入口要求。当前入口与能力以活动组合及本文件对应场景为准。
- 本规格是行为说明，不代替授权校验、迁移兼容性和隔离验证；这些仍按项目自己的门禁执行。
