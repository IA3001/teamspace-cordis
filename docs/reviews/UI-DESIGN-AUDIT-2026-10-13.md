## 视觉判断与应保留的部分

整体印象偏配置面板拼接，缺少一致的产品框架。问题不是主色不好看：
同样的数据管理任务采用不同容器；有的页面大片留白，有的页面把操作挤到下方；
卡片、状态块、分区线与标签竞争注意力。统一组件库只是起点，仍需统一组合与状态规则。

本次至少检查了六组具体设计点：

1. 容器：资源页三种不一致的布局；知识库文件夹面板随内容收缩，工作区多层嵌套。
2. 排版：后台页标题实测 21px、说明 13px、常用表单/标签 14px；字体基本一致，但结构层级和重复标题仍有问题。
3. 图标：机器人和书本重复作为不同入口；导航链接没有明确可访问名称。
4. 配色：后台/知识库近黑底，团队管理/资源页灰黑底；错误白粉色大块与其余暗色界面视觉权重差异明显。
5. 留白与密度：知识库首屏剩余大量未使用空间；工作区有限高度被说明和状态容器占用。
6. 状态与动作：供应商表单操作区左右不一致；记忆详情和小桌面分页失去可达性；处理历史可进一步紧凑。

应保留而不是推翻：

- Agent 管理已采用左侧选择、右侧编辑，方向正确；分组表单比旧卡片列表清楚。
- 知识库、记忆库、工作区已有目录树，以及列表/详情分工，不应重新退回平铺卡片。
- 当前 1440×900 下三个资源页与 Agent 管理未出现 document 全局滚动。
- 模型列表已按供应商隔离，错误有解释与重试入口；这些行为不应因视觉重做而回退。
- 登录页主体居中、必填项清楚，是相对完整的一页；品牌“TS”与外壳“Cordis/团队空间”仍需统一。

## 建议的设计顺序与验收

先解决 01–06 的阅读、导航和操作可达性，再统一资源框架，最后整理视觉细节。
下一轮设计先交付四组明确原型：全局导航、供应商列表/编辑、资源管理器、聊天/Agent 执行状态。
每组必须包括正常、加载、失败、空数据、长文本和多数据状态，不能只画漂亮的静态首屏。

约束沿用项目铁律：Element Plus / k-*、共享组件和既有设计令牌；不得再引入第二套视觉体系。
Agent 管理保留左选右改，资源管理保留层级组织，后台与 Team 身份边界保持明确。
桌面验收至少覆盖 1440×900 与 1100×720，手机仍暂缓。

新增验收应检查：

- 分页、保存、重试的矩形完全位于可见内容容器内，不能只检查 document 是否溢出。
- 长正文自然换行；详情内容及元信息可在内部滚动区域完整读取。
- 目录、列表、历史、详情各自可滚动；扩展或状态更新不改变用户选中项、展开节点与滚动位置。
- 相同任务的字段名、按钮顺序、表单布局和状态语义一致。
- 所有图标操作都有明确名称，键盘可到达，焦点可见。
- 处理中提供真实阶段、工具调用摘要、耗时与最近更新；断线/失败与成功视觉语义明确区分。
