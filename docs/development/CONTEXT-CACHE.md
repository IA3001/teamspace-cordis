# 上下文前缀缓存

Agent 执行请求按以下顺序组织：稳定系统规则（身份、提示词、按 ID 排序且获准的工具、工作区与引用规范）→ 历史 → 本轮动态资料（实时待办、召回记忆、检索结果、当前可交接成员）→ 当前任务。工具循环保留已有消息，只追加工具请求与结果。

`space-context` 提供 `stableSystem` 与 `dynamicContext`；原 `system` 字段保留兼容旧消费者。执行路径使用分离字段，不把变化的来源 ID、待办或检索结果拼回固定前缀。前缀稳定来自内容组织，不是把过期数据放入本地缓存。Agent 身份、工具授权、配置或历史撤回变化会自然改变对应内容。

执行路径的历史使用 `cache-blocks`：每 8 条事件移动一次起点，保留目标最近 30 条及最多额外 7 条；预算不足时按块删旧历史。零条请求返回空历史，撤回事件不注入。固定规则与动态资料优先，若它们本身超过预算，`approxChars` 如实反映占用，不偷偷删掉规则或把待办状态伪装为空。没有自动生成有损历史摘要。

OpenAI 兼容适配器请求 `stream_options.include_usage` 并读取末尾仅含 usage 的 SSE 帧。工作记录保存输入、输出、缓存命中 Token、首个可见文本延迟和总耗时；不保存原始提示词或凭据。不支持该请求字段的供应商可以在 LLM 插件配置中关闭 `streamUsage`。缺失缓存统计显示“供应商未报告”，不解释为零。统计回调失败不能导致任务失败，也不会把生成中的状态改回处理任务。

`verify:context-cache` 检查前缀稳定、数据新鲜、历史边界、预算、撤回、身份区分和流式缓存统计；已纳入 `verify:rag` 与相关 CI 路径。它验证请求结构和统计解析，不冒充真实供应商的缓存命中结果。

方舟的隐式缓存按相同前缀匹配，受模型支持、最小 Token 门槛、保留时间及路由影响；请求结构正确不保证每次命中。是否有效须观察供应商返回的真实用量。[方舟缓存说明](https://docs.volcengine.com/docs/ark/context-cache?lang=zh)。
