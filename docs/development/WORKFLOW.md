# Agent-Native 开发流程

这是开发流程的权威出处；[AGENTS](../../AGENTS.md)仅提供导航。范围不包括产品内 Agent 改造。DSH 参考版本固定为 `d743267388641bc76f17c45ce8b4c231aed1d32c`，采纳状态见[矩阵](ADOPTION.md)。

## 从任务到交付

1. 读取当前规范和相关能力，盘点工作树；禁止提交不属于任务的改动。新任务在独立工作树中工作，不能把 HEAD 工作树误当作包含未提交内容的快照。
2. 用[任务模板](task.example.json)填写目标、验收、允许目录、运行面。`npm run dev:task -- create <id> <spec.json>` 建立本地任务，记录基线与源码指纹；同名任务不得覆盖。
3. 在干净基线上，`npm run dev:task -- worktree <id> <绝对新目录>` 建立 detached 工作树；需要分支时自行在工作树创建任务分支。不自动提交或复制本地数据、凭据。已有脏基线必须先由用户确认归属及合适的保存方式。
4. 实现保持本次范围，验证行为而不是源码特定写法。修改接口后运行 `npm run docs:generate`，检查 `npm run gate:docs`。查看 `npm run gate:related -- <base>` 的选择和完整收据；交付前仍运行完整 `npm run gate`。
5. `npm run dev:task -- checkpoint <id> <note.json>` 记录阶段、事实和剩余项。`resume` 显示指纹是否变化；旧收据不会因为 checkpoint 更新而重新有效。
6. `attach` 接收成功且同版本收据；`review` 接收独立审查者、作者、HEAD、指纹与发现。自报身份只代表本地记录，不是密码学身份或平台强制审批。
7. 单人直接推送流程不要求 PR 或人工逐项批准。推送前运行相关检查和完整 `npm run gate`；GitHub Actions 在 push 后再次运行完整 CI。CI 不调用 LLM 审查。`release <id> <receipt.json>` 只生成准备状态，不执行 merge/publish；发布或部署仍需对应发布流程授权。

检查图、隔离与报告详见[CI](../CI.md)。真实模型验证只允许人工显式在线入口；fork/无 Key 不得声称在线模型验收通过。

## 交接与可观察信息

记录目标、基线、工作树、修改范围、真实地址、检查收据、已知失败、决策链接和剩余工作。`notes` 只写结论与可复核事实，禁止密钥、生产内容和隐藏推理。生成产物/本地报告在 data，任务模板与技能入库，实际收据不入库。

运行面是任务的环境事实，不是产品接口。浏览器必须断言期望 origin、页面关键内容、交互与 console/pageerror；若服务地址或构建变化，重新确认并验收。HTTP 200、另一个端口、截图漂亮都不能替代行为验证。

## 决策、历史与兼容

当前规范允许随实现修订，历史复盘封存后不覆盖。新决策使用[模板](decision.example.md)写问题、选项、取舍和验证；归档 hash 受可信基线比较。兼容性变更登记写受影响接口/格式、旧版本、升级、回退限制和夹具测试；数据库、事件和索引变化不能只补一句“已兼容”。升级与发布先复用现有备份恢复和 release-start 测试，不新增业务格式。

## 权威与历史状态

用户已明确取消后台登录要求，当前后台入口不增加登录墙；原账号隔离/登录叙述中与此冲突的内容属于历史要求，不作为重新加登录的授权。架构文档旧 `/code` 等输入和全局单会话章节保留历史说明，当前产品行为以已批准决策与实现回归为准；本开发工程不改变它。

平台流水线接入方式见[单人自动验证流程](PLATFORM.md)；GitHub Actions push 后失败只提供反馈，不能阻止该次 push。
