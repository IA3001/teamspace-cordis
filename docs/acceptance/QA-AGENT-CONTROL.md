# Agent 可控协作 QA 计划

本文把 [Agent 会话收件、按需访问与人类中继目标场景](gherkin/06-agent-control-model.feature) 转成可执行的 QA 计划。它验证本轮确认的产品设计，不代表其中所有能力已经实现或本文件中的所有用例已经通过。

## 1. 目标与验收原则

验证以下行为形成一个完整闭环：

1. 会话中的每条人类消息都会到达所有已加入该会话的 Agent；Agent 各自静默处理并维护自己的游标。
2. 被动 Agent 不公开发言；允许主动发言的 Agent 按规则判断、节制发言，定向 `@` 回复优先。
3. 默认上下文有界且缓存友好；记忆仅少量基础注入，详细记忆与知识库通过显式、受限的访问方法按需获取。
4. Agent 系统访问能力按会话、Agent 和工具授权隔离，操作可追溯。
5. 每个 Agent 只能写自己的个人工作区；共享工作区对 Agent 只读。
6. Agent 不能互相直接派发任务；人类必须审阅、编辑（可选）并确认中继。
7. 故障、重启、撤回和并发不会造成漏处理、重复副作用或越权访问。

**验收标准：**所有 P0 用例通过；所有 P1 用例通过，或被明确登记为待实现；没有跨会话读取、Agent 私有数据串用、Agent 间自动派发、工作区越界写入或凭据泄漏。P0/P1 不得以截图、单一 HTTP 200 或模型自述替代可观测证据。

## 2. 优先级和测试层级

| 优先级 | 含义 | 失败处理 |
| --- | --- | --- |
| P0 | 隐私、安全边界、人类中继、数据一致性 | 阻止验收；修复并完整重跑相关用例 |
| P1 | 核心收件、发言控制、上下文、系统访问契约 | 核心产品验收不得标通过；可以登记实现缺口 |
| P2 | 状态可读性、性能指标、易恢复性和 UI 易用性 | 记录问题与影响，进入后续修复 |

| 层级 | 验证内容 | 环境 |
| --- | --- | --- |
| 单元/策略 | 发言策略、游标边界、上下文排序、授权判定 | 隔离测试夹具 |
| 服务集成 | Inbox、event log、memory、retrieval、tool registry、workdir | 临时数据库和临时文件目录 |
| 运行时 | 多 Agent、多会话、重启恢复、队列竞争、失败重试 | 项目隔离 gate 环境 |
| 浏览器 | 成员发言、Agent 进度、记忆/知识按需调用、人类中继确认 | 专用验收实例和浏览器 |
| 供应商联调 | 流式响应、缓存 token、真实模型行为 | 单独授权的验收凭据；与普通 gate 分开 |

普通 QA 应使用确定性的 mock LLM、Embedding 与代码执行替身。真实供应商验收只证明该供应商、模型和当时配置的表现，不替代隔离回归，也不能在没有单独授权时运行。

## 3. 隔离环境与测试数据

### 运行要求

- 只使用临时数据库、临时文件目录和专用端口；禁止对生产或共享开发实例执行写入型用例。
- 依照项目工作流使用隔离的 `gate:static` / `gate:runtime`。手动 `verify:*` 或 `smoke` 可能接触当前开发实例；执行前必须确认运行面。
- 使用新建数据库并应用正式迁移；禁止让测试夹具自行创建业务表来掩盖迁移缺失。
- 测试阶段和结论按项目要求记入 action log，并保存 `data/ci` 收据、逐项日志和必要浏览器截图。凭据、真实会话内容和隐藏推理不得进入 QA 报告。
- 所有测试账号、会话、Agent 和文件使用 `qa_` 前缀，结束后删除临时环境；若环境不能安全清理，保留隔离工作区并记录位置。

### 固定夹具

| 名称 | 类型 | 设置 |
| --- | --- | --- |
| `qa_human_a` | 人类用户 | 会话 `qa_session_a` 成员；DRI 权限仅在需要决策用例中授予 |
| `qa_human_b` | 人类用户 | 仅会话 `qa_session_b` 成员，用于跨会话拒绝检查 |
| `qa_agent_passive` | Agent | 已加入 session A；`speechPolicy=passive`，`memoryPolicy=agent` |
| `qa_agent_proactive` | Agent | 已加入 session A；`speechPolicy=proactive`，确定性模型配置 |
| `qa_agent_memory_none` | Agent | 已加入 session A；`memoryPolicy=none` |
| `qa_agent_uninvited` | Agent | 在团队目录中，但未加入任何验收会话 |
| `qa_agent_relay_target` | Agent | 已加入 session A，作为人工中继目标 |
| `qa_session_a` | 开放会话 | 成员为 human A 与上述已邀请 Agent |
| `qa_session_b` | 开放会话 | 仅 human B 和单独的 Agent 成员；写入唯一 canary 文本 |
| `qa_shared` | 团队共享工作区 | 放置只读 canary 文件 `docs/qa-shared.txt` |

Mock 模型至少支持以下脚本化输出：静默处理且无记忆、写入一条带来源的记忆、请求主动发言、拒绝主动发言、发出一个允许工具调用、请求未授权工具、流式部分输出后断开、超时、可重试 5xx 和不可重试认证错误。每个响应必须能按 Agent ID 与来源事件 ID 确定。

## 4. 访问控制基线

执行所有读取类用例时，同时检查成功数据和拒绝结果；拒绝响应不得包含被拒绝资源的文本、标题、文件名或存在性线索。

| 主体 | 会话事件/待办 | Agent 私有记忆 | 个人工作区 | 共享工作区 | Agent 发言/派发 |
| --- | --- | --- | --- | --- | --- |
| 会话成员人类 | 当前在册会话 | 按产品界面授权范围 | 管理界面允许范围 | 团队共享范围 | 可发言、可确认中继 |
| 已加入该会话的 Agent | 当前会话授权范围 | 仅自身 Agent scope | 仅自己的读写区 | 只读 | 可按 speech policy 发言；不能直接派发另一 Agent |
| 未加入会话的 Agent | 无该会话访问权 | 仅自身 scope | 仅自己的区 | 仅在工具策略允许时读取 | 不接收该会话新消息 |
| 其他会话成员 | 仅其在册会话 | 无他 Agent 私有记忆 | 无其他 Agent 个人区 | 共享只读范围 | 不得伪造另一用户中继 |

如果某项访问策略与产品最终授权模型不一致，先修订访问矩阵并由产品负责人确认，再将对应拒绝用例视为最终验收标准。

## 5. 详细用例

### A. 消息扇出与静默收件

#### QA-INBOX-001 — 人类消息扇出到每个在册 Agent（P0）

**前置：** session A 中至少有三个状态可运行的 Agent，游标均已追平；session B 有不同 canary。

**步骤：**

1. 记录各 Agent 在 session A 的当前游标。
2. human A 发送一条唯一文本 `qa-human-event-001`，不含 `@`。
3. 等待所有 Inbox waiter 完成。
4. 分别查询各 Agent 的 cursor、处理记录和模型调用输入。

**预期：**消息只追加一次；每个在册 Agent 的游标均越过该事件；每个 Agent 的处理来源均指向同一 event ID；未加入的 Agent 没有该事件处理记录；没有公开 Agent 回复，除非该 Agent 配置了主动策略且规则允许；事件内容不得流向 session B。

#### QA-INBOX-002 — 被动 Agent 消息处理不产生公开回复（P1）

**前置：** `qa_agent_passive` 开启记忆提取，mock 返回一条记忆但不返回回复文本。

**步骤：**发送无提及的人类消息并等待收件处理；读取时间线、Agent 记忆和私有处理 trace。

**预期：**收件游标推进；符合策略的记忆带来源 event ID 写入 Agent 私有 scope；时间线没有该 Agent 的普通回复；后台 trace 可解释“已处理/已静默”，且 trace 不进入其他 Agent 上下文。

#### QA-INBOX-003 — 定向提及不会让其他 Agent 抢答（P0）

**前置：** mock 让 proactive Agent 对任何未抑制消息都请求发言；session A 中有两个以上 Agent。

**步骤：**human A 发送 `@qa_agent_relay_target 请检查 qa-task-003`；等待所有在册 Agent 的 cursor 追平。

**预期：**目标 Agent 收到一次定向任务；其他 Agent 仍收到事件并推进游标，但不替目标公开回复、不重复执行同一任务；收件和目标回复均可用 event ID 串联。

#### QA-INBOX-004 — Agent 邀请后只从邀请边界开始收件（P1）

**步骤：**先在会话中产生消息，再邀请 `qa_agent_uninvited`，记录邀请游标并发送新消息。

**预期：**Agent 不会在未受邀时处理会话；受邀后仅按定义的 onboarding 策略读取允许的历史范围；新事件顺序处理且不跳号、不重复写副作用。

#### QA-INBOX-005 — Agent 回复被其他 Agent 静默接收（P1）

**步骤：**让 `qa_agent_relay_target` 在 session A 追加结果，然后检查其他已加入 Agent 的 cursor 和处理 trace。

**预期：**其他 Agent 按静默/主动策略处理该结果；原作者不重复处理自己的事件；不产生 Agent 间私有消息通道。

#### QA-INBOX-006 — 重启后恢复未处理事件（P0）

**步骤：**暂停 mock 或进程，使一个 Agent 的游标落后；追加两条事件；在处理完成前重启隔离服务。

**预期：**开放会话恢复后从旧游标继续按序处理；已成功完成的模型副作用不重复；关闭会话不重新创建 Inbox trace；恢复成功/失败状态可在运行日志和验收收据中查到。

#### QA-INBOX-007 — 多会话排队不串上下文（P0）

**步骤：**让 Agent A 在 session A 处理中时，向 session B 写入带唯一 canary 的消息；按调度队列完成两边处理。

**预期：**每个请求的 `sessionId`、历史事件、记忆 scope 和结果来源均属于自身会话；session A 的模型请求中找不到 session B canary，反向亦然。

### B. 主动发言策略

#### QA-SPEECH-001 — 被动策略阻止主动回复（P0）

**步骤：**配置 passive Agent；mock 明确要求它主动发言；发一条无提及消息。

**预期：**统一策略拦截公开消息；可执行静默记忆策略；处理结果记录拦截原因。

#### QA-SPEECH-002 — 主动策略先判断并允许选择沉默（P1）

**步骤：**配置 proactive Agent；mock 分别返回“无需补充”和“需要补充”两种结果，各发送不同来源事件。

**预期：**第一种没有公开消息；第二种仅在策略允许时产生一条带来源关联的回复；两个结果都可从后台处理摘要区分。

#### QA-SPEECH-003 — 连续主动发言被限制（P0）

**步骤：**触发一次允许的 proactive 回复；不经过任何人类定向提及，再触发另一条可主动发言事件。

**预期：**第二次自动回复被拒绝；提示或处理记录包含限制原因；不得用系统提示伪装成 Agent 的普通答案。

#### QA-SPEECH-004 — 人类 `@` 可以定向唤起受限 Agent（P1）

**步骤：**在 QA-SPEECH-003 后由 human A 明确 `@` 该 Agent 并给出新任务。

**预期：**目标 Agent 的定向响应可以通过；该响应被标记为定向回复，后续策略状态按规则重置。

#### QA-SPEECH-005 — 新定向事件淘汰过期主动判断（P1）

**步骤：**延迟旧消息的 proactive mock；随后发送明确 `@` 该 Agent 的新任务；再放行旧 mock。

**预期：**旧消息不再补发过期回复或提示；新定向任务正常处理；来源关系没有错绑。

### C. 上下文与缓存友好性

#### QA-CTX-001 — 请求消息保持稳定前缀排序（P1）

**步骤：**对同一 Agent/会话连续执行两轮任务，捕获完整模型请求并对比。

**预期：**稳定 system 规则和工具目录位于前部；已存在历史保持原序；动态资料在独立段；本轮 task 在尾部；新增事件不导致整个旧历史重新格式化；任务文本不进入 system 规则。

#### QA-CTX-002 — 历史窗口和字符预算有界（P0）

**步骤：**填充超过 recent limit 与字符预算的长会话，包含短事件、长事件、撤回事件和系统 trace；组装 Agent 上下文。

**预期：**历史数量/字符不超过规定窗口；从旧历史侧按块裁剪；撤回事件和 Agent 私有处理 trace 不进入上下文；system 规则和必要来源标记优先保留。

#### QA-CTX-003 — 追加消息只扩展活动历史块（P2）

**步骤：**比较块边界前后各一次请求，确认既有消息对象和内容顺序。

**预期：**未跨边界时仅追加新事件和动态资料；跨边界时仅按约定淘汰最旧完整块；不得每条消息全量重建所有既有上下文。

#### QA-CTX-004 — 不同 Agent 的 system、工具和动态资料隔离（P0）

**步骤：**为 Agent A/B 设置不同角色、工具 allowlist 和私有记忆 canary；同一会话中分别触发任务。

**预期：**模型请求 A 不含 B 的提示词、私有记忆和工具；请求 B 不含 A 的对应内容；两者仅共享当前会话被授权的历史和资料。

#### QA-CTX-005 — 供应商缓存用量如实展示（P2）

**步骤：**Mock SSE 一次返回 cached token usage，一次不返回 usage，一次在结束帧报告用量。

**预期：**已报告用量显示准确值；缺失时显示“供应商未报告/未知”，不得写成 0 或沿用旧请求数据；过程摘要不暴露 prompt 密钥。

### D. 记忆和知识库按需访问

#### QA-MEM-001 — 基础记忆注入数量受限（P1）

**步骤：**为 Agent 准备远多于基础上限的记忆，并标记不同 scope、来源有效性和敏感 canary；执行普通任务。

**预期：**只注入策略许可的有限基础记忆；不把全库倾倒进请求；无效来源和其他 Agent 记忆不注入。

#### QA-MEM-002 — 按需记忆检索返回来源（P1，目标能力）

**步骤：**触发一个不在基础记忆中的已知事实；让 Agent 调用记忆搜索工具，分别使用命中词和无命中词。

**预期：**命中结果包含 memory ID、来源 event ID 和有效状态；无命中明确返回空结果；搜索只读；请求记录为该 Agent 的工具调用。

#### QA-MEM-003 — 私有记忆隔离和撤回失效（P0）

**步骤：**Agent A 写入私有 canary；Agent B 搜索相同 canary；随后撤回源事件，再搜索并组装上下文。

**预期：**B 从未读取到 A 的私有记忆；撤回后该记忆不再作为有效搜索/注入结果；如果有剩余有效来源，重建内容仅依赖剩余来源。

#### QA-MEM-004 — `memoryPolicy=none` 阻止记忆写入（P0）

**步骤：**令无记忆 Agent 处理多个有明显事实的消息；检查内存表、上下文和游标。

**预期：**收件游标仍推进，但 Agent scope 不产生新的语义记忆；运行 trace 标记策略关闭。

#### QA-KB-001 — 普通无关任务不自动带入知识库文档（P1，目标能力）

**步骤：**在 KB 放置唯一文档 canary；执行明确与文档无关的任务；捕获 LLM 请求。

**预期：**请求中没有该文档正文或自动检索片段；系统不读取全库作为默认上下文。

#### QA-KB-002 — Agent 显式搜索返回有限引用片段（P1，目标能力）

**步骤：**让 Agent 通过 KB 搜索方法提交查询；再用另一个查询重复；审查模型最终引用。

**预期：**只返回有上限的相关 chunk，带文档 ID/标题；答案引用必须匹配真实结果；错误、空结果或关键词回退不得生成虚构引用。

#### QA-KB-003 — 知识搜索授权和供应商故障（P0）

**步骤：**先撤销 Agent 的 KB 工具权限并调用；再恢复权限但让 Embedding 超时；保持关键词检索可用时重复搜索。

**预期：**未授权调用被拒绝并留下工具拒绝记录；Embedding 故障可按产品策略回退关键词搜索或返回明确错误；不可把其他 scope 的文档作为回退结果。

### E. Agent 系统访问方法

#### QA-ACCESS-001 — 会话历史搜索受成员范围和分页限制（P0）

**步骤：**当前会话和 session B 分别放置同一关键词；在 session A 让 Agent 搜索并翻页，再尝试指定 session B。

**预期：**只返回 session A 的事件；分页游标稳定、不重复不漏项；越权请求被拒绝且不泄露 session B 标题或内容。

#### QA-ACCESS-002 — 待办读取属于当前会话并含稳定条目标识（P0）

**步骤：**在两个会话各创建不同待办；Agent 读取当前会话列表并尝试跨会话 ID 访问。

**预期：**返回当前会话待办的 ID、文本和完成状态；跨会话读取失败；刷新和分页/列表重排不会把 ID 指向另一条待办。

#### QA-ACCESS-003 — 待办变更权限需要单独授权（P0）

**步骤：**用只有读权限的 Agent 分别尝试新增、完成和删除待办；再用被明确授予某项写权限的 Agent 测试允许操作。

**预期：**默认读权限不能写；每种授权独立生效；人类通过 UI 变更后 Agent 再读可见更新；审计标注实际操作者。

#### QA-ACCESS-004 — 工具 allowlist、参数校验和审计完整（P0）

**步骤：**分别调用已授权工具、未分配工具、全局禁止工具、缺字段参数和畸形 JSON。

**预期：**只有授权且参数有效的调用执行；其他调用得到稳定失败结果；输入、输出摘要和拒绝原因可追溯；敏感参数被脱敏；失败不能被记作成功。

#### QA-ACCESS-005 — 工具不能绕过 seam 直接访问实现（P0）

**步骤：**尝试通过提示注入让 Agent 输出或执行跨 scope 数据库查询、任意文件路径和未注册 API。

**预期：**只有工具注册表暴露的能力能调用；路径和身份由服务端重新校验；模型提示不能扩大权限。

#### QA-ACCESS-006 — 敏感信息跨界脱敏（P0）

**步骤：**在工具参数、文件内容、模型错误和 Agent 结果中放置测试格式的 bearer、API key、password；检查模型 trace、UI 活动记录、日志和 action log。

**预期：**敏感值不出现在普通 UI、审计摘要或错误提示中；只显示已隐藏占位；原始秘密不得写入 QA 收据。

### F. 工作区隔离

#### QA-WD-001 — 每个 Agent 独占个人工作区（P0）

**步骤：**Agent A 写 `notes/qa-private.txt`；Agent B 尝试用自己的工作区读取同一路径并枚举目录。

**预期：**A 能读写自己的文件；B 看不到该文件；成员 UI 选择不同 Agent 时显示对应工作区，不把路径根目录混用。

#### QA-WD-002 — 共享工作区对 Agent 只读（P0）

**步骤：**A/B 读取 `docs/qa-shared.txt`；两者分别尝试覆盖、删除和创建共享文件。

**预期：**授权策略允许的 Agent 都能读取共享文件；Agent 写入工具拒绝所有共享区变更；共享文件 hash 保持不变。

#### QA-WD-003 — 工作区越界、符号链接与审批边界（P0）

**步骤：**请求 `../` 路径、工作区外符号链接、目录本身及超过 1 MB 普通文件；再对合规普通文件发起审批。

**预期：**越界读取不能直接返回内容；允许审批的文件建立去重请求；非普通文件/超限文件不能进入审批；批准复制源文件发生变化时拒绝交付。

#### QA-WD-004 — Agent 写文件规范和代码执行限制（P1）

**步骤：**依次尝试合规路径、根目录散落文件、过大内容、重复危险文件名和超限代码执行。

**预期：**合规 personal 路径可写；违规输入被拒绝；代码只在受控执行环境运行；共享区仍只读；失败状态和输出上限可观察。

#### QA-WD-005 — 配额错误可见且不会无限重试（P1）

**步骤：**模拟 quota unavailable、ENOSPC 和普通权限错误。

**预期：**相关操作停止；配额错误写运行日志并给会话添加可操作系统提示；普通权限错误不误报为配额；不在失败后反复写入扩大损坏。

### G. 人类中继与协作审计

#### QA-RELAY-001 — Agent 建议后不自动触发目标（P0）

**步骤：**让 Agent A 输出建议由 Agent B 执行的结构化后续任务；不点击中继入口并等待队列静止。

**预期：**Agent B 没有收到新事件、没有运行、没有待处理计数变化；没有隐藏 direct-message 或后台委托。

#### QA-RELAY-002 — 人类可审阅、编辑并确认中继（P0）

**步骤：**human A 打开建议；检查目标 Agent、来源回复和草拟任务；修改任务文本；按发送确认。

**预期：**确认前没有派发；确认后新增一条可见的 `@Agent B` 会话消息，作者为 human A；内容是人类最终确认的文本；B 通过常规 Inbox 收到该事件；事件可追溯到来源建议。

#### QA-RELAY-003 — 取消中继不产生副作用（P0）

**步骤：**打开建议后取消/关闭；再修改目标为未加入当前会话的 Agent 并尝试确认。

**预期：**取消不生成消息；未加入目标被拒绝且没有事件/任务副作用；人类可先邀请目标后重新发起中继。

#### QA-RELAY-004 — 不能伪造人类中继作者（P0）

**步骤：**修改客户端请求作者 ID，或重放另一用户的中继请求；同时检查服务端登录身份。

**预期：**事件作者由已认证人类身份决定；请求体伪造无效；未登录、非会话成员和无效 token 均不能中继。

#### QA-RELAY-005 — 同一建议重复确认幂等（P1）

**步骤：**快速双击确认或在响应超时后重试相同操作。

**预期：**只创建一次中继事件和一次 Agent 执行；UI 提示已发送/处理中；重放响应不会再创建副作用。

### H. 浏览器可观察性和故障恢复

#### QA-UI-001 — 私有收件 trace 不混入聊天（P0）

**步骤：**打开会话时间线、活动面板、Agent 工作区和搜索结果，检查一条已完成收件 trace。

**预期：**用户可在明确的 Agent 活动/管理区域看到处理阶段和摘要；普通聊天正文、Agent 上下文和导出纪要不包含内部 trace 或原始模型思维链。

#### QA-UI-002 — 处理状态真实且错误可恢复（P1）

**步骤：**依次触发排队、执行中、模型超时、凭据错误和重试成功。

**预期：**状态反映实际阶段；可重试网络/服务错误按策略重试；永久认证/模型错误停止自动重试并提示修复配置；页面轮询失败不清空已有数据。

#### QA-UI-003 — 中继和拒绝操作均有明确反馈（P1）

**步骤：**完成一次确认中继、一次取消、一次权限拒绝。

**预期：**页面明确告知发送成功、取消无副作用或被拒绝原因；错误与成功反馈互不覆盖；用户可从时间线找到实际已发送事件。

#### QA-OBS-001 — 回归命令结果和人工证据可追溯（P1）

**步骤：**按第 6 节运行关联验证和 gate；查看 `action_log`、5172 数据库页/日志页及 `data/ci` 收据。

**预期：**每项检查有真实退出码、耗时和状态；失败、跳过、超时不得记为通过；汇报结果能定位到检查名、收据和具体日志。

## 7. 当前实现差距与进入验收的条件

| 能力 | 当前代码基线 | 目标验收前置条件 |
| --- | --- | --- |
| 所有消息对所有已加入 Agent 静默扇出 | 有持久 Inbox/cursor；有提及时未定向 Agent 当前可能只推进游标，不做记忆/主动判断 | 明确事件覆盖矩阵，并通过 QA-INBOX-001/003 |
| 主动发言策略 | 已有 passive/proactive 和连续主动限制 | 定向、非定向、后续 `@` 竞态规则通过 QA-SPEECH 全组 |
| 缓存友好上下文 | 已有稳定前缀、块历史、动态资料、任务尾段 | 证明增量维护和隔离，不扩大默认历史，QA-CTX 全组通过 |
| 记忆按需工具 | 有有限基础记忆注入和后台记忆提取；缺显式 Agent 搜索工具 | 注册受 Agent scope 限制的 memory access，并通过 QA-MEM 全组 |
| KB 按需工具 | 当前 Agent 任务上下文按 query 自动检索；缺 Agent 显式 KB tool | 将显式调用与默认组装分开，并通过 QA-KB 全组 |
| 系统访问工具 | 会话历史、待办、KB、记忆等由系统部分注入或 UI 侧读取；Agent 工具注册不完整 | 建立稳定的 tool contract、权限矩阵和审计字段，通过 QA-ACCESS 全组 |
| 人工中继 | Agent 链接由人点击后直接发送预设任务；没有独立审阅/编辑/确认 | 增加确认 UI 与幂等服务端操作，通过 QA-RELAY 全组 |

只有前置条件完成后，才将目标用例从“待实现”改为“待验收”；实际验收通过后再记录 gate 收据、浏览器证据与结果。不要把现有相似命令的通过状态推断为新目标能力已通过。
