# 对照 teamspace-cordis：可借鉴什么

本节对照调研时的本地工作树，而非声称这些变化已经提交、部署或受平台保护。保留已有 UI TODO；研究衍生任务位于 [独立 TODO 分组](../../../../TODO.md#dsh-agent-native-todos)，本轮不执行这些改造。

## 已有机制应保留

| 机制 | 当前证据与价值 | 与 DSH 的差别 |
| --- | --- | --- |
| 分层与可替换能力 | `packages/seam`、`impl`、`policy`、`client-ui`；AST 依赖检查及负向夹具，L0–L12 方向 | DSH 的 seam 是完整能力族，不等于本项目 `seam/` 目录；不能直接重命名套用 |
| 隔离 CI | `scripts/ci.mjs` 创建副本、空外部密钥、临时数据库/端口，迁移与 seed 后运行检查；有超时、清理、JSON 报告 | 本项目顺序执行并收集失败；DSH 使用 DAG、并行和部分 fail-fast。目标不同，顺序本身不算缺陷 |
| 真实产品验证 | UI、生产启动、工作区、消息队列、向量索引等 focused verification | 已覆盖不少真实路径，不能描述成“只有 lint”；仍需检查是否绕过真实 Loader 或只匹配源码字符串 |
| 范围与规则预算 | `.ci/checks.json`、`scripts/lint-changes.mjs`、复杂度/文档大小/改动预算，规则变更对照可信 Git 基线 | DSH 文档预算只覆盖指定 standing docs；没有找到它的统一圈复杂度上限，不能借其名义扩大规则 |
| 持久化与向量身份 | SQLite migrations、embedding identity 与索引切换/取消回归 | 已有模型变化处理，不能再以“完全没处理重新向量化”为前提；应补版本兼容与升级证据 |
| 代码审查入口 | CODEOWNERS、CI 文档和仓库流水线入口 | 配置存在不等于 Gitee 已启用必需检查、规则修改者独立审批；平台设置尚未核实 |

本地阅读路线：[CI 说明](../../CI.md)、[CI 检查清单](../../../.ci/checks.json)、[隔离执行器](../../../scripts/ci.mjs)、[依赖检查](../../../scripts/lint-layers.mjs)、[组合器](../../../src/compose.ts)、[向量索引回归](../../../scripts/verify-embedding-index.ts)。这些链接指向本地现状，日后可能变化；DSH 证据仍固定 SHA。

## 衍生任务与验收

成本指相对实现与长期维护成本，不是未经排期的工时承诺。

| 编号 / 优先级 | 实现范围 | 成本与依赖 | 验收条件 |
| --- | --- | --- | --- |
| DN-01 / P1 | 文档权威归属、当前状态与历史决策分开；检查后台登录等旧描述是否与已批准方向冲突 | 低；先确认现有规则与用户已批准决策 | 每类事实只有一个权威来源，其余链接；旧文档明确历史状态；README、AGENTS、部署说明与实际入口无矛盾 |
| DN-02 / P1 | 相对链接/锚点检查；从稳定源码生成工具、RPC、配置的最小目录，检查新鲜度 | 中；DN-01，先选一类接口，禁止读取真实密钥 | 删除锚点、增加未登记接口、修改权限/参数后对应门禁失败；重新生成通过；生成两次无 diff |
| DN-03 / P1 | 公共服务/API 文档示例编译及关键接口与文档等价检查 | 中；先选少量稳定接口；本项目 TS 7 与 DSH TS 6 API 不同，需选兼容解析方案 | 示例类型错误失败；源码字段变化而文档未变失败；明确豁免清单；不把可编译误当行为正确 |
| DN-04 / P1 | 独立可信规则审查及实际平台保护核实 | 中；需要仓库管理员权限，当前平台以实际托管设置为准 | 规则/测试删除不能靠同一 PR 修改审批算法绕过；无独立批准、检查缺失/跳过时阻止合并；记录真实设置与受控演练证据 |
| DN-05 / P1 | 沿真实 profile、Loader、发布产物验证服务注入与页面入口；审计依赖源码文本匹配的行为验证 | 中；复用现有隔离启动与浏览器夹具 | 改坏真实注入/发布资源时失败；原运行地址刷新可验收；运行状态故障不能展示成功；不删除已有有效测试 |
| DN-06 / P2 | SQLite、消息事件和索引持久化变更登记，升级/reader 兼容、失败恢复说明 | 中；DN-01，复用现有迁移与向量索引测试 | 对已支持旧版本夹具升级且内容保留；中断重试不混入不同模型向量；不可回退变更明确说明与备份要求 |
| DN-07 / P2 | 开发相关检查选择与验证收据；先收集各检查耗时，再决定并行 DAG | 中；DN-05，保留隔离与完整 CI | 选择依据绑定 base/head 与变更文件；报告区分通过/失败/跳过/中止；独立 lane 故障不伪绿；改造前后同环境有耗时与遗漏率记录 |
| DN-08 / P2 | 组合器与当前安装 Cordis 的 Patch 语义差异测试 | 中；先固定当前 Cordis 版本，不引入整个 vendor | 插入、配置、重复 ID、disabled、合法表达式等夹具得到一致结果；不一致有公开规则与可定位报错 |
| DN-09 / P2 | 按真实替换需求检查能力 Definition/Provider/Consumer 边界，先审计 Embedding 抽象所在位置 | 中；需第二实现或跨提供者消费证据再拆包 | 业务消费者依赖稳定契约；替换实现不改 UI/Agent 工具协议；层级检查通过；无为统一名字而全仓重构 |
| DN-10 / P2 | 轻量决策记录与开发交接模板，保存问题、选项、取舍、检查及未完成项 | 低；DN-01 | 下一轮 Agent 可定位当前约束、运行面、验证结果和剩余工作；记录不含密钥与隐藏推理；不复制整套 DSH 双语/封存流程 |

DN-05 的可见执行状态与原地址浏览器证据，关联现有 **UI-10** 及工作区/UI 验收任务；本组只补工程验收机制，不另建一份 UI 产品清单。UI 视觉统一与滚动修复仍按原分组推进。

## 暂不引入

- **加权 blame 审批整套算法。** DSH 允许合格 bot 参与，并非固定两个人类批准；本项目规模下先用独立审查和受保护规则，复杂积分易增加解释与维护负担。
- **全部 vendor 和完整业务子系统。** 是否 fork Cordis 取决于实际框架缺口、补丁维护能力和升级责任；当前不能以 DSH 采用 vendor 就推导本项目必须采用。
- **完整覆盖率 100% 或 DSH 全部门禁。** 它有明确排除范围，ACP 事故也证明覆盖率不能替代消费者路径。先保护关键行为和真实启动，再评估覆盖率收益。
- **JSONL generation 直接替换 SQLite 迁移。** 可借鉴发布版本、兼容性登记、流式/有界处理的原则，格式与迁移机制要服从当前架构。
- **Agent 隐藏思维链展示。** 可见工作阶段、工具参数/结果、错误、重试、耗时及简要执行说明已足以形成审计；不把私有内部推理当作产品验收要求。

建议顺序为文档权威 → 一致性检查和可信审查 → 真实消费者验证 → 兼容性及测量 → 有证据的组合/边界调整。研究只能证明值得验证的机制；任务全部保持未完成，不能把调查结论当成已实施功能。
