# DSH 的 Agent-Native 开发与 Cordis 架构调研

调研日期：2026-10-13。研究基线：`d743267388641bc76f17c45ce8b4c231aed1d32c`，根包版本 `0.2.1-alpha.2`，提交时间 2026-10-09。所有历史结论使用固定提交或标签，避免浮动文档覆盖旧决策。此次只新增研究文档和 TODO，没有改业务代码、CI 或数据库。

## 先读这五个结论

1. **DSH 从项目起步就选了 Cordis。** 最早可达历史中的第二次提交已写明 Cordis 与微内核设计，随后才加入 monorepo、vendor、接口和 Agent 循环。公开证据支持“沿 Cordis 扩展产品”，不支持“已有成熟单体后来适配 Cordis”。最初飞书设计文档无法访问，不能声称复原了完整选型讨论。[开发历史](history.md)
2. **Agent-Native 的重点是可执行的开发环境。** 它让 Agent 能发现规则与接口、按变更选检查、得到可定位失败、保留决策，并让行为沿真实启动路径被验证。公开事故包含 DSH Web Agent 修改自身 GUI 的事件序号，是自用证据；这仍不等于完整开发会话已全部开源。[开发流程](agent-native.md)
3. **代码/文档一致性是一组不同检查。** 可编译示例、源码类型与 JSDoc 等价、生成目录新鲜度、链接、持久化变更记录、双语配对分别控制不同漂移。通过 hash 不等于语义正确，通过类型检查不等于产品可用。[CI 与文档](ci.md)
4. **它也经历了“大门禁太慢”和“测试全绿、产品坏掉”。** 本地全量 pre-push 后来被缩小；CI 移除不必要的跨 job 构建依赖。ACP 事故说明 100% 覆盖率仍可能绕过真实 Loader。GUI 事故说明 HTTP 200 和另一个端口上的成功不是原页面验收。[六个案例](cases.md)
5. **当前项目应先补一致性和证据闭环，再考虑复杂架构。** 已有隔离门禁、目录分层与行为测试值得保留。优先建立文档权威归属、接口目录新鲜度、真实组合路径回归、兼容性说明和相关检查选择。暂不照搬复杂加权审批、全部 vendor 或完整 DSH 功能族。[项目对照](project-mapping.md)

## 本次调查做到什么程度

扫描了基线可达的 21,405 个提交的标题与日期，以及 2,069 个 first-parent 提交；不是阅读每个提交的全部 diff。基线有 1,224 份带日期的英文决策笔记：924 archived、251 implemented、41 proposed、8 rejected；中英文不重复计数。挑选关键提交、源码和笔记重建变化，并将六个案例的实现时间与主线合入时间分开记录。[机器记录](evidence/baseline.json)

实际运行了审批策略 80 项测试、两个基线门禁，以及五类正向/负向探针：文档预算、Markdown 锚点、源码类型与文档等价、配置来源、历史档案封印。修改只发生在临时夹具或隔离的上游副本，结束后还原；未运行完整上游构建、付费模型、生产迁移或整套浏览器矩阵。[验证记录](evidence/verification.json) · [复现方法](verification.md)

证据等级：**D**＝源码/提交/公开记录直接可见；**I**＝多份直接证据支持的推断；**U**＝此次未能核实。笔记中的历史性能数据标为维护者记录，不伪装成本机重新测量的结果。

## 必须保留的证据边界

- 决策笔记、产品测试用 JSONL 和完整研发对话不是同一类资料。未发现可公开复核的完整研发会话归档。
- 早期提交带有 Codex review 的明确描述；这支持特定审查参与，不证明所有代码由 Agent 完成或没有人类介入。
- 官方仓库中保留大量历史 PR 合并号；本次直接请求 #5946 的公开 PR API 在官方与旧组织均返回 404。因此历史审查正文、批准者和全部 CI 执行日志未能恢复。
- 可读 CI 配置能证明执行设计，不能独自证明当前保护分支实际启用。审批测试通过，也不能证明所有发布都遵守了它。
- 公开 Actions API 样本主要是依赖更新，不能代替本研究基线完整 CI 的执行证据。

这份报告不认定 DSH 已“保证高效”。它解释哪些机制帮助 Agent 开发、哪些事故推动了机制变化，以及哪些效果仍缺可比较数据。
